Blender:
Pros:

  • Industry standard compared to a home-made rendering engine. Makes it easier to work with other people and transfer skills in in industry
  • A lot of resources available online in how to achieve a lot of different effects
Cons:
  • Not as flexible as a renderer engine. Even though Blender is Open-Source, it is not as easy to modify since there is so much more logic involved than just the renderer
WebGPU:
Pros:
  • Very flexible. Any feature can be implemented (in theory). There are some browser limits that Blender does not have, however most techniques should be able to be implemented in WebGPU
  • More low-level control to rendering pipeline, allowing custom passes and similar non-trivial renderer features
Cons:
  • Need to implement every material "from scratch" (can reuse code)
  • May spend more time implementing renderer features than on the end product you're trying to produce
There is not really anything that comes to mind that I do not have access to in Cycles that WebGPU offers. Maybe lower-level access to render passes could be useful in some context.

One thing that would be hard to implement in WebGPU would be Blender's shading system. Blender's node system makes it very fast and easy to create new materials, can combine the results of shaders and nodes. In WebGPU we need to write new shading code (possibly reusing code) when we want a new material. In Blender it is much faster to iterate on parameters and make complex materials from simple nodes. If one wanted to implement this in WebGPU, one should probably compile a nodegraph to WGSL which would not be trivial.
